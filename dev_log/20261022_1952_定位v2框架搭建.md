## 1. 背景

空目录上搭建 naiad_algodash_localization_v2。目标是水面准静态对准、水面 RTK/IMU 紧组合、水下大船坐标系 IMU+轮速、出水快速搜星后再紧组合，水面/水下自动切换。算法核来自 gnss_imu_couple，船体公式以 man/ins-hull-rel.md 为准，输入输出用 ROS2。

## 2. 讨论脉络

- gnss_imu_couple 的可执行文件是文件后处理（tc-postpos / rnx2rtkp），源码集中在 src/ins-gnss。
- 现有 naiad_localization 的传感器话题为 fog/data、motion/odometer、sensor_depth/data、sensor_rtk/data、sensor_xcar/data，输出 robot/odometry。
- 拷入 ins-gnss、公共头、地磁系数、船体/里程计/RTK 笔记和 carvig-tc.conf。未拷视觉工程、plot、tools、theory.pdf、图像解码和 ins-vo.zip。
- 新增 ROS2 包 naiad_localization_v2：相位机 + 紧组合桥 + 船体融合入口。默认不编译 ins-gnss。
- Humble 下 cmake 配置并编译通过。节点只发 localization_v2/status；solution_valid 为假时不发里程。

## 3. 结论

- 框架说明和逐文件职责在 man/framework.md。
- 水下优先于 RTK：没出水面不进紧组合。水面失锁走 resurface_search，不改走船体融合。
- 陆地 odo/nhc/zvu/zaru 保留源码，船体模式禁止调用。
- 滤波方程尚未从 ins-gnss-tc.cc 和 ins-hull-rel.md 接到 GnssTcBridge / HullFusion。filter_wired 保持 0。
- 压力阈值 dive_on_bar=1.20、dive_off_bar=1.12 需实船标定。无有效深度时按水面处理。
