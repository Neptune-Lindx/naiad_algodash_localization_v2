## 1. 背景

模式 A 第一步：把 v1 的 `robot_set_position_service` 迁到 v2，但行为按新要求改。没有 RTK 时轮速为 0 才写初始状态；有 RTK 时只留准静态对准入口，不写对准方程。

## 2. 讨论脉络

v1 服务名 `algo/set_position`，类型 `naiad_interfaces/srv/RobotSetPosition`。旧逻辑依赖任务参数、坐标变换，后轮 RTK 有效时还会改 xyz 并 reset KF。本步不搬这些门控。

本版本不订阅 `sensor_rtk/data`，所以 `rtk_available()` 固定返回 false，无 RTK 分支是当前唯一会成功的路径。

## 3. 结论

- 服务仍叫 `algo/set_position`。
- 无 RTK：必须已收到 `motion/data` 和 `fog/data`。`wheel_velocity[3]` 与 `real_velocity` 绝对值都不超过 `wheel_speed_zero`（默认 0.001）才接受。
- 接受后写入 `HullFusion::ModeAOrigin`：大船系位置 = `req->position`，速度 0；全局锚点经度 114.0°、纬度 30.0°、高度 0，全局速度 0；姿态取 `fog/data` 的 roll/pitch/yaw（度）和 orientation 四元数。
- 不把 `solution_valid` 置真，不发 `localization_v2/odometry`。
- 有 RTK：调用 `GnssTcBridge::start_quasi_static_align()`。该函数现在返回 false，服务回 `RET_NOT_IMPLEMENTED`。对准方程未写。
- 缺轮速 `RET_NO_MOTION_DATA`，轮速非 0 `RET_FAILED`，缺 fog `RET_NO_FOG_DATA`。
- 包内 cmake 编译通过。安装走 `./build.py -b naiad_localization_v2`。
