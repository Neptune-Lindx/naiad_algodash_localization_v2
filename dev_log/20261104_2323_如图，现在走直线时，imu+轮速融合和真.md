### 末轮助手（摘录）

直线段重合，说明对外的右前上和真值图画在同一套水平轴上。整段 xy 对调会在直线上就已经错开，所以这次转弯才分开，不是输出坐标轴反了。

转弯才出现的差，来自角速度和杆臂的叉乘。直线时 `ω≈0`，叉乘是 0，杆臂错了也看不出来。

现在的实现和你说的顺序不是同一条链：

1. 各轮速度是一步折到 IMU 的：`v_fog = (v, 0, 0) - ω × (fog_to_rear + rear_to_wheel)`，而且只用前向分量。分成「先到后轮中心，再到 IMU」在速度数值上等价，但杆臂只改了量测 `z`，没有进预测 `h`，也没有进 `H`。位置列和陀螺零偏列都是 0，姿态列里也没有 `∂(ω×l)/∂φ`。文档第 5.1 节写的预测是 `v + ω×l`，代码没有按这个做。
2. 导航方程积分的是 IMU 上的比力和角速度，位置、速度状态都是 IMU 点。融合后再投回后轮中心时，用的是 `lever_fog_to_rear_center`。这份配置里它是 `[0, 0, 0]`，所以这一步是空的，发出来的位置和速度仍是 IMU，不是后轮中心。
3. 非完整性约束仍把机体系右向、下向速度拉成 0，速度门和角速度门已经去掉。侧向那一行的航向系数里有 `-v_x`。直行时侧向新息接近 0，航向几乎不动；转弯时侧向残差变大，航向会被拉偏，轨迹就从弯里分开。
4. 前轮没有转向角。转弯时前轮编码器速度不沿车体前向，代码仍把它当成 `(v, 0, 0)` 去对 IMU 前向速度。这也只会在转弯里出来。

所以杆臂补偿不完整是主因，但不是唯一原因。轮速杆臂只补在量测前向分量上；IMU 到后轮中心的位置、速度搬运因为杆臂写成 0 而没有生效。转弯时 NHC 改航向、前轮无转向角，会把弯再拉开一截。

```87:89:src/motion_data_handle.cpp
//   A
//   |
// B--O--C
```

转弯角不是用陀螺某一轴的瞬时值，而是用相邻两帧 FOG 姿态，只取绕车体 y 轴（上）转过的角。注释写明：正角度是绕 y 正转，也就是左转。角度为 0 时，各轮里程原样等于 O 点里程。

角度不为 0 时，左右轮按半轮距 `OC` 收成 O 点弧长：

- 外侧轮：`d_O = |d| - |θ|·OC`
- 内侧轮：`d_O = |d| + |θ|·OC`

哪边是内侧，由转角和左右轮速度符号一起判断。`angle` 与速度同号时，左轮当内侧、右轮当外侧。

前轮多一个轴距 `OA`。先用前轮自己的弧长求转弯半径，再收回 O 点：

```154:157:src/motion_calibration.cpp
ra = abs(distance) / abs(to_radian(angle));
rc = sqrt(ra * ra - OA_ * OA_) - OC_;
ro = rc + OC_;
distance_calibrated = abs(ro * to_radian(angle)) * sgn2(distance);
```

`ra` 是前轮到转弯中心的距离，`ro` 是后轮中心到转弯中心的距离。前轮走的弧更长，这里把它缩成 O 点走过的弧。半径小到机械极限以内，这只轮的校正里程直接丢掉。
