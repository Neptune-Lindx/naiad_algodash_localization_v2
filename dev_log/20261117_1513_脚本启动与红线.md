# 脚本启动和 ros2 run 的红线

> 保存时间：2026-11-17 15:20 (UTC+8)
> 工作区：naiad_algodash_localization_v2
> 触发方式：主动收尾

## 1. 背景

脚本启动后姿态图经常没有红色定位曲线。`ros2 run` 每次都有。红线是 `plot_imu_odo` 从 `/localization_v2/status` 的 `rpy_n` 画的，没有这段字段就不画。

## 2. 讨论脉络

对照了 `scripts/local_planning_control_test/start_localization_sim.sh` 和本包的 `start_neptune_sim_localization_v2.sh`，并看了 2026-11-17 各次 `logs/neptune_sim_*/naiad_localization_v2.log`。

## 3. 结论

- 这些脚本启动都设位成功。姿态大约横滚 90°、俯仰 −3°。里程计话题当时能 echo 到。其中 12:44 那次节点一直跑到 14:48 才被 stop。
- 红线数据和里程计同一拍写出。节点在跑的时候，status 里就有 `rpy_n`。
- 和旧仿真脚本的差别：旧脚本用 `naiad_n1_v4.yaml`（`use_sim_time: false`）加 `robot_n1_sim.yaml`，并导出 `NAIAD_DATA_DIR` / `NAIAD_DB_DIR` / `NAIAD_CONFIG_DIR`，先 `algo/transform` 再设位。`motion/data` 跟随 `motion/control`，没有指令时也是 0。v2 脚本只带 `localization_v2.yaml`，发全 0 的 `motion/data`，不调用 transform。
- v2 滤波轮速来自 `/motion/odometer`，不读 `motion/data`，也不解析 robot profile。这些差别不会让 `rpy_n` 消失。
- `ros2 run` 和脚本是同一个二进制、同一份 yaml。脚本停在 `Waiting for set_position` 时按 Ctrl+C，节点会一起收到 SIGINT 退出。2026-11-16 19:10 那次就是这样。
