# 红线和黑线起点有时不重合

> 保存时间：2026-11-17 15:20 (UTC+8)
> 工作区：naiad_algodash_localization_v2
> 触发方式：主动收尾

## 1. 背景

Gazebo 里黑线是船体系真值，红线是 `/localization_v2/odometry`。红线起点有时不落在黑线起点上。

## 2. 讨论脉络

世界文件 `neptune_cleaning_floating_dual_demo.sdf` 里红线 overlay 的 `frame` 是 `truth_start_offset`。对齐在 `ShipRelativeTrajectoryVizSystem.cc` 的 `OverlayPoseToShipLocked`。

## 3. 结论

- 偏移只算一次：`黑线第一个点 − 红线当时的位置`。之后每帧红线都加这个固定量，并且 `realign_gap_seconds` 是 0，定位节点重启也不会重算。
- 第一帧红线到达时如果黑线还没有点，这一帧的位置被记下来，但这个点不画。真正画出来的是后面一帧。两帧位置不同，红线起点就偏离黑线起点。Gazebo 和定位谁先有数不稳定，所以有时重合、有时不重合。
- 黑线起点是仿真一开始机器人在船上的位置。设位把红线拉回 (0,0,0) 后，插件仍把红线接到那个历史起点，不是接到设位时刻机器人脚下的位置。

## 4. 涉及文件与引用

- `neptune-sim/sim/worlds/neptune_cleaning_floating_dual_demo.sdf` 的 localization_v2 overlay（只读）
